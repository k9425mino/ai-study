# Change Stack과 Code Peek 활용

CodeRabbit Review의 Change Stack은 큰 PR을 파일명 순서가 아니라 변경의 논리적 흐름에 따라 읽도록 돕는 리뷰 화면입니다.

> Change Stack의 제공 플랜, Git 제공자, 얼리 액세스 여부는 변경될 수 있습니다. 현재 사용 가능 여부는 CodeRabbit 화면과 공식 문서에서 확인하세요.

## Cohort와 Layer

하나의 PR에 서로 다른 기능과 수정이 섞여 있으면 파일 목록만으로는 맥락 전환이 잦아집니다. Change Stack은 변경을 독립적인 작업 단위인 Cohort로 묶고, 각 Cohort 안에서 이해하기 좋은 Layer 순서로 정리합니다.

리뷰할 때는 다음 순서로 살펴봅니다.

1. Cohort 요약에서 변경 목적을 파악합니다.
2. 데이터 모델과 공통 타입처럼 기반이 되는 Layer부터 읽습니다.
3. 해당 기반을 사용하는 비즈니스 로직과 인터페이스를 따라갑니다.
4. 테스트와 설정 변경이 앞선 변경을 충분히 뒷받침하는지 확인합니다.
5. 서로 관련 없어 보이는 Cohort가 한 PR에 섞인 이유를 검토합니다.

큰 AI 생성 PR에서 특히 유용하지만, Cohort가 많다는 사실 자체가 PR 분리 신호일 수도 있습니다.

## Code Peek

Code Peek은 diff에 등장하는 함수, 클래스, 타입, 변수의 정의와 사용처를 리뷰 화면 안에서 찾는 기능입니다. 다른 탭으로 이동해 검색하고 원래 리뷰 위치를 잃는 비용을 줄여 줍니다.

### 활용 질문

- 이 함수의 실제 구현은 어디에 있는가?
- 이번 변경 외에 어떤 호출자가 영향을 받는가?
- 이 타입 변경이 다른 Layer로 어떻게 전파되는가?
- 변경된 심볼이 PR 밖의 기존 코드와 호환되는가?

검색 결과가 현재 PR의 변경 파일을 가리키면 Change Stack 안에서 해당 위치로 이동할 수 있습니다. 탐색 기록을 이용해 호출 관계를 따라간 뒤 원래 diff로 돌아옵니다.

## Chat Agent

Chat Agent는 PR 전체 변경 맥락을 바탕으로 질문에 답합니다. 막연하게 “요약해 줘”라고 묻기보다 검증 가능한 질문을 사용합니다.

```text
이 API 응답 타입 변경에 의존하는 호출자를 경로별로 정리해 줘.
인증 로직 변경이 실패 경로에 미치는 영향을 설명해 줘.
이 이름 변경이 시작되는 지점부터 외부 인터페이스까지 추적해 줘.
테스트에서 다루지 않은 오류 경로를 찾아 줘.
```

답변은 탐색을 돕는 가설로 취급하고, 실제 코드와 테스트에서 근거를 확인합니다.

## 심각도와 Effort로 우선순위 정하기

Change Stack에서는 리뷰 지적을 Critical, Major, Minor, Trivial로 분류해 볼 수 있습니다.

- Critical: 보안 침해, 데이터 손실, 서비스 중단처럼 머지를 막을 가능성이 큰 문제
- Major: 실제 사용자 영향이나 주요 로직 오류로 이어질 수 있는 문제
- Minor: 품질과 유지보수성을 개선하지만 즉시 머지를 막지는 않는 문제
- Trivial: 표현, 스타일, 작은 정리 수준의 제안

먼저 Critical과 Major의 재현 가능성과 영향도를 확인합니다. Comment type과 수정 Effort 필터를 함께 사용하면 “중대한 잠재적 이슈이면서 빠르게 고칠 수 있는 항목”처럼 현실적인 우선순위를 만들 수 있습니다.
